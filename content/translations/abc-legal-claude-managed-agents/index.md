> 原文：[How ABC Legal turned every employee into a builder with Claude Managed Agents](https://claude.com/resources/articles/how-abc-legal-turned-every-employee-into-a-builder-with-claude-managed-agents)；原作者：Anthropic；原文发表：2026-08-17

今年早些时候，当美国法律文书送达服务巨头 ABC Legal 的首席技术官（CTO）布兰登·富勒（Brandon Fuller）面向全公司 1,100 名员工推广 [Claude 企业版（Claude Enterprise）](https://claude.com/solutions/enterprise?utm_source=chatgpt.com) 时，某种质变瞬间发生了。全公司各个团队——无论是诉讼文书送达、法院电子立案、出庭律师调配，还是市场、法务合规、财务部门——在没有任何人催促指令的情况下，自发开始动手搭建各种自动化工作流。

“大家真的像潮水一样涌了进来，”富勒回忆道，“看到连接器和工具竟然这么容易上手，全公司各个部门的人突然都开始动手，把那些长年累月吞噬他们大量精力的重复工作自动化。”

这本是每位 CTO 梦寐以求的普及景象。但富勒敏锐地看到了更上一层楼的契机：如果 ABC Legal 能够运行一支具备版本控制、可全面观测、且 7×24 小时永不停机的 **AI 智能体集群（Fleet of AI Agents）**，会发生什么？

实现这一雄心的关键，归根结底在于底层基础设施。早期员工自建的智能体极其分散：散落在各个开发者的个人电脑桌面，作为本地的定时任务悄悄运行。只有将它们从个人电脑迁移出来，智能体才能实现真正的无人值守；也只有这样，富勒才能在一张全局看板上对“全公司到底构建了哪些智能体、耗费了多少成本、昨晚它们是否正常运转”了如指掌。

为此，他果断部署了 [Claude 托管智能体（Claude Managed Agents）](https://platform.claude.com/docs/en/managed-agents/overview?utm_source=chatgpt.com)：一套标准统一的部署架构、共享的工作空间、单一的审计与账单视图，以及直接部署在云端、无需依赖个人笔记本电脑的常驻智能体。

截至 2026 年 7 月，富勒与 ABC Legal 团队交出了这样一份成绩单：

- 超过 **50 个**基于 Claude 托管智能体构建的应用成功接入生产环境；
- 在未经深度精细优化的前提下，部分智能体覆盖的原本由人工处理的任务，成本降低了最高达 **~50%**；
- 全公司各个部门有约 **310 名员工**在日常业务中高频使用 Claude。

以下是他们如何一步步达成这一目标，以及在整个转型历程中沉淀的宝贵经验。

## 从热情到工程化：把每一个智能体都视作软件

在首次部署 Claude 托管智能体时，富勒给团队定了一条铁律：**必须把每一个智能体都定义为代码（Define every agent as code）**。他坚信这才是智能体的天然形态。正如他所剖析的那样：“智能体本质上就是结构化文本——一段提示词（Prompt）加上一组配置项（Configuration）。只要是文本，就可以存放在 Git 代码仓库里，供全公司所有人公开查阅、严谨审查并协同改进。”智能体的系统提示词、工具列表、调度计划、认证凭据和上下文记忆，全部被写入配置文件，与公司的软件代码库并肩存放在同一个 Git 仓库中。任何针对智能体的修改，唯一被允许的途径就是提交一个经过他人严格审查并批准的 Pull Request（PR）。这样一来，每一个智能体都天然获得了版本历史记录、同行代码审查、一键版本回滚，以及无法篡改的完整审计追踪日志。

富勒花了一周时间搭建了一个脚手架（Starter Kit），其中包含存放在独立 Git 仓库中的两个核心模板：一个是**事件驱动型智能体（Event-driven agents）**，一旦特定事件触发（例如新任务派发或法院退回了文书），它便会即刻启动；另一个是**定时调度型智能体（Scheduled agents）**，按既定时间周期运行（按小时、每日或每周）。每个智能体都封装在具备标准目录结构的独立文件夹中：一个 JSON 配置文件、一份 Markdown 格式的系统提示词、自动化部署脚本以及运维文档。一旦修改被合并到主干分支（main），系统就会全自动部署该智能体。业务人员根本不需要自己去写复杂的程序代码——他们只需克隆仓库，复制一份脚手架模板，用自然语言告诉 Claude Code 这个智能体需要完成什么任务，Claude Code 就会全自动生成该智能体所需的一切：配置、提示词、凭据定义以及记忆上下文。

## 跨越技术鸿沟：让非程序员也能独立造出生产级智能体

富勒召集了由 15 位来自财务、市场、业务运营以及业务拓展部门成员组成的公司指导委员会（他们当中没有一个是专业的软件工程师），要求他们亲自动手克隆代码仓库，并利用 Claude Code 构建属于自己的托管智能体。

此举的目的，是彻底证明即使是非开发人员，也完全有能力独立构建出面向生产环境的智能体。如果每一个智能体的需求都必须排队等待 IT 研发团队消化，这种交付瓶颈将彻底扼杀整家公司的创新步伐。而之所以能保证这一过程的安全可靠，是因为他们根本不需要去编写底层软件代码——他们只需填写业务配置和核心提示词，底层的运行时环境由 Claude 托管智能体全权接管。

“我一开始还得跟他们耐心地解释到底什么是 PR。好多非研发同事一开始还以为 PR 是体育里‘个人最好跑步成绩’（Personal Record）的意思呢，”富勒笑着回忆道，“而现在，他们每天都在熟练地提交 Pull Request，互相审阅对方的代码变更。”

短短一周内，这 15 名非技术员工全部做出了能够实际运行的业务智能体。随后，这批“先锋构建者”回到各自的业务部门，担当起培训其他同事的导师。不到一个月的时间里，ABC Legal 内部就已经有大约 50 多个智能体在各条业务线上井然有序地奔跑。每个智能体都有专属的代号、明确的负责人以及单一专注的职责。

## 贯穿法律文书送达全流程的智能体矩阵

如今，ABC Legal 在法律文书送达与诉讼流程的几乎每一个核心环节及其外围运营中，都部署了专门的智能体。

- **AI 代码审查员（AI Code Reviewer）**：全天候把关横跨四个代码库的每一次 Pull Request，运行多模型深度交叉分析，排查安全漏洞、性能衰退隐患以及不小心硬编码提交的敏感凭据。如今，工程师们在合并代码前都会习惯性地等待它的审查意见。
- **EvidenceChain™ 交付智能体**：接管了一位客户经理此前每周必须手动处理的苦差事。ABC Legal 运营着一个名为 EvidenceChain.com 的专有平台，法院、原告和被告可以在该网站上查询现场送达的详尽凭据记录，包括送达人员是谁、尝试送达的具体时间，以及文书交付现场的照片存据。某家大客户提出需要定期持续从该平台拉取特定案件的记录。如今，该智能体每天会自动拉取匹配条件的数据库报告，利用托管智能体内置的浏览器抓取对应的 PDF 凭证，并自动分发上传至该客户的 FTP 服务器。那位最初搭建它的客户经理此前从未做过任何自动化工作，他只是用自然语言向 Claude Code 清晰描述了业务需求，仅花了一个小时就完成了该智能体的搭建。
- **电子立案驳回诊断专家（eFiling Rejection Diagnoser）**：一旦法院驳回了某份立案申请，它就会自动启动，瞬间读取案件细节，对照该法院的地方法律细则进行逐条比对，并在短短一分钟内将诊断结果精准推送到 Slack 频道——以往这项繁琐的排查工作往往要耗费员工几个小时的宝贵精力。
- **案件核验智能体（Job-Verification Agent）**：在系统接收到任何新任务时，自动前往对应法院系统进行比对核验。它会通过无头浏览器自主导航访问法院官方网站，确认听证会或案件是否已经按规范立案、确切开庭日期是否与登记一致，并根据核验发现动态校准任务属性，自动标注对应司法管辖区、审理法庭以及诉讼时效期限。
- **出庭律师排班调度助手（Attorney Coverage Agent）**：穿梭于庞大的出庭律师协作网络中，主动核实出庭排期意向，自动发送沟通邮件，解析律师们关于空闲时段与收费报价的回复，供人工调度员进行最终一键确认。
- **财务应收账款处理智能体**：自动解析收到的汇款回单邮件，生成 NetSuite 财务系统的付款核销文件，推送到 Slack 供财务人员一键审批并自动导入；此外还有每日智能体负责针对研发工单自动做出“属于资本化开支还是费用化支出”的财务合规判定。
- **营销 Google Ads 投放分析师**：每周定期向营销渠道负责人输出量化投放优化建议。
- **运营质检审阅员 Charvis**：专门审查已完成的送达服务工单，其质检判定结果与专业合规审查团队的吻合度高达 **98%**。
- **催办推进助手（Service-Overdue-Nudger）**：专门攻坚 ABC Legal 运营积压任务中的第一层日常工作，接管了以往人工执行的重复初筛，每天自动草拟分级的业务跟进沟通话术，交由人工确认后一键触达。

## 让智能体自主进化：“收割、调优、循环”

ABC Legal 的所有智能体都在人类员工的严密监督下工作。它们会将自身执行的操作或建议实时推送到 Slack 频道，员工可以在对应的讨论串（Thread）中跟帖回复，或通过 Emoji 表情给予即时反馈。

![内部代码审查智能体 Hank 将每次审查结果推送到公共 Slack 频道。](https://assets.claude.com/8f900037eb2f484fefedada30cfe8e50e744453b.png)

*内部代码审查智能体 Hank 将每次审查结果推送到公共 Slack 频道。每条记录都会标明对应的 PR 和统计指标，使智能体决策链条完全透明且可被随时检索。*

富勒敏锐地意识到，Slack 里的所有员工互动反应数据，原本都是被白白浪费掉的宝贵训练信号。当然，并不是每个智能体都需要这种精细调优——集群中的多数智能体都是单任务执行器，它们的输出不需要被打分，独立静默运转即可。而对于那些需要根据人工打分持续精进的智能体，ABC Legal 创新设计了一套**三角色协同架构**：多个独立的智能体共享同一个工作空间、运行环境和凭据保险库，但按不同的时间节奏触发。这套模式巧妙地将 Slack 里的日常对话消息，转化为由人类审核批准的版本化配置变更：

1. **初始执行智能体（The Initial Agent）**：在业务现场实时执行任务（例如新工单录入或收到法院文书时），并详细记录每一次操作的审计日志。
2. **收割者（The Harvester）**：按小时或按天定期运行，自动采集员工在 Slack 讨论串中的文字回复以及表情符号（Emoji），将每一个交互细节沉淀为带有清晰业务标签的结构化数据点。
3. **调优者（The Tuner）**：每周定期汇总审视所有积累的数据，并针对系统提示词（Prompt）或配置文件主动提出优化建议，而不是去微调底层模型的权重。它仅负责起草变更建议，由人类工程师审阅通过后以 Pull Request 的形式正式合并生效。

*在 ABC Legal 的自进化智能体闭环中，初始智能体实时执行业务，收割者每小时捕获 Slack 中的人类反馈，每周调优者以 Pull Request 的形式提出提示词与配置优化建议。智能体通过与人类开发者完全相同的日常流程实现自我进化。*

这套架构的一个典型代表是“**交付即代码（Deliveries-as-Code）**”系统——这是富勒为优化工单路由派发而设计的智能体协同体系，最早在其拥有 50 名员工的姊妹公司 Docketly 落地。Docketly 的核心业务围绕各种外勤交付任务展开，每类任务都有一套专属的派单与处理规则。所有这约 145 套业务规则集全部以独立的 YAML 文件形式保存在 Git 仓库中，而不是隐藏在后台繁杂的管理后台界面里。因此，调整某类文书的派送规则，就等同于编辑一个配置文件并提交一个 Pull Request。

整个迭代闭环由四个智能体协同运转：一个智能体每周在 Slack 发出派单裁决建议；“收割者”根据员工的反馈互动将表情与回复转化为标签数据；“调优者”针对 YAML 规则文件自动发起 Pull Request；第四个智能体则在人类审批合并后，将最新配置推送到生产数据库中。请注意，这第四个执行智能体只能运行经过人类同行彻底审查通过的规则。在实际业务中，员工在 Slack 里针对某个派单失误点下的一个 Emoji 标记，能在短短一周内直接演变为一条被正式合并入生产环境的代码规则修改。在整套闭环中，人类的介入仅仅是最后的审核把关。

## 为什么选择 Claude 托管智能体

在最终选定 Claude 托管智能体作为全公司的核心基础设施前，富勒曾严谨评估了市面上的多款技术框架。他的选型标准非常严苛：平台必须原生支持版本控制、会话级全局可观测性、精细的工作空间账单计费、灵活的模型切换能力、开箱即用的上下文记忆原语、无缝的 MCP（模型上下文协议）支持，而最核心的一条是——**绝不能让团队耗费精力去给底层基础设施当保姆**。

Claude 平台的职责划分，与富勒期望的运营治理模型完美契合。Anthropic 的托管底座全权接管了让智能体跑起来所需的一切底层脏活累活：执行循环（Execution Loop）、会话管理、记忆存储、控制台界面以及前沿大模型本身的计算能力。而 ABC Legal 只需全神贯注于自身的核心资产：提示词工程、工具链列表、业务触发逻辑、全链路审计记录以及成效反馈闭环。

在规模化落地过程中，以下几项能力展现出了不可替代的价值：

- **完备的版本控制**：每一次代码推送都会通过乐观锁机制生成全新的智能体版本，版本回滚轻而易举。
- **极致的模型调用灵活性**：绝大多数智能体默认采用性价比卓越的 Claude Sonnet；针对超高并发、极度追求低延迟的任务切换至极速轻巧的 Claude Haiku；而当复杂的逻辑推理值得付出更高成本时，则无缝调用旗舰级的 Claude Opus。切换底层模型只需修改一行配置。
- **强大的 MCP 串联与凭据保险库**：智能体可以安全可靠地直连 ABC Legal 内部自研系统（开放了超过 100 种专用业务工具）、用于数据报表的 Metabase、用于人机协同的 Slack，以及用于项目管理的 Atlassian 工具链。
- **开箱即用的定时调度部署**：周期性运行的智能体直接由 Bitbucket Pipelines 的 Cron 机制调度托管，天然继承现有的代码权限管控、密钥管理以及计费体系。

ABC Legal 严格追踪 AI 的每一分钱开支，按供应商、工具、团队和具体业务场景精细分摊。随着智能体集群在春季全面铺开，开支起初曾有所攀升；但到了 7 月份，尽管调用规模与使用人数持续暴增，整体成本却开始显著下滑——这正是下文所述降本增效优化的直接体现。在日常工作中深度使用 Claude 的全员员工达到约 310 人的同时，诸多智能体所接管的业务任务成本实现了约 50% 的显著下降。

公司的成本管控逻辑非常明确：**将预算重兵倾斜向具备清晰可衡量 ROI 的垂直、业务运营型智能体，同时保持通用的水平对话与脑暴工具的广泛覆盖并将其成本牢牢控制在合理区间**。绝大多数智能体在设计之初都严格遵循“人在回路（Human-in-the-loop）”原则：智能体在分析工单或需求后，首先给出处理建议，等待业务人员确认无误后再行动。建议可以直接内嵌在业务工单的顶部横幅中，方便员工在日常流转中一键接受或驳回；或者直接发布在 Slack 频道供员工在讨论串中回复。这些真实互动沉淀为高质量的好坏样本数据集，反哺给“收割者”和“调优者”闭环，让工程师能够编写科学的自动化评测集（Evals），并在前沿大模型迭代时进行基准横向测评。一旦某个智能体在特定任务上的表现被充分证实达到甚至超越了人类专家的水准，它就会平滑切换为全自主自动化运行模式，并在上线后继续处于相同的指标监控框架下，全天候严密防范任何性能滑坡。

ABC Legal 核心跟踪的指标是<strong>“效率产出比（Efficiency Ratio）”</strong>——即智能体带来的实际业务价值与运行该智能体所耗费成本的比值。每一个托管智能体在每次执行完成后，都会以工时和金额的形式向数据仓库实时上报其创造的价值。智能体的投资回报往往呈现经典的 **J 曲线效应**：新上线初期，由于缺乏针对性优化且通常使用大模型，往往处于暂时亏损的“水下状态”；但随着工程团队为其编写严密的评测用例、将其平滑切换至更小更快的轻量模型，并精简上下文 Token 开销，其效率收益便会迅速反弹飙升，强势转正。

## 规模化部署智能体集群的最佳实践

富勒在率队部署 Claude 托管智能体的实战征程中，沉淀出了几条含金量极高的工作准则：

1. **万物皆可代码化（Think of everything as code）**。“代码本质上就是结构化文本，而大语言模型本身就是最强劲的文本处理引擎，”他说，“你能够把越多公司的日常业务逻辑转化为 Git 仓库里的纯文本，智能体能为你撬动的杠杆就越巨大。”这不仅适用于传统软件开发，同样无缝适用于提示词、Schema 契约、调度分发规则、通知模板以及所有业务配置。
2. **务必始于“人在回路”（Start with humans in the loop）**。每一个智能体的生命周期，都必须从“给出建议供人类审查”起步。唯有在实践中持续证明其决策与人类专家高度一致后，它才具备独立行动的资格。“每个智能体都必须凭实力一步步赢得团队的信赖，而不是从第一天起就获得完全放手的特权。”
3. **将 Pull Request（PR）作为唯一的控制面**。“如果你希望智能体参与某项业务决策，就请把这个决策过程重塑为一个 Pull Request。”行级差异比对、严密的审批流以及不可篡改的审计追踪，这些版本控制系统自带的天然护城河，能够无比自然地将 AI 生成物与人类的同行审查融合在一起。
4. **重金投资反馈闭环（Invest in the feedback loop）**。“收割者-调优者”模式意味着智能体无需重新训练底层模型即可持续自我进化。Slack 中的一条简单回复、一个 Emoji 反应，都能转化为结构化的调优信号，最终通过人类早已驾轻就熟的 PR 流程，反哺为提示词与配置的迭代。
5. **果断跳过“本地定时任务”的弯路**。ABC Legal 在早期曾耗费大量精力去折腾单机定时任务和本地脚本，很大程度上是因为当时托管平台还在公测早期。富勒给如今想要入局者的忠告非常明确：直接拥抱云端托管智能体，不要在本地零散任务上浪费时间。
6. **做好面对“Git 学习门槛”的准备，而不是 AI 门槛**。整个落地过程中最艰巨的挑战，并非教业务人员如何理解 AI，而是如何让非技术同事适应克隆仓库、使用 Git 分支以及提交 Pull Request。事实证明这条路不仅行得通，而且见效极快，但这确实是一道客观存在的门槛；富勒也真诚希望未来的工具链能够让这一协同流程变得更加平滑。
7. **并非所有任务都配得上拥有一个智能体（Not every task deserves an agent）**。运行成本是客观存在的，团队必须时刻保持“价值大于成本”的清醒算盘。核心工作在于精准识别那些真正具备规模化落地价值、能切实节省工时或打通自动化堵点的真痛点；面对那些食之无味的小需求，要有说“这个任务不值得专门做一个智能体”的战略决断力。

## 未来展望

ABC Legal 的智能体舰队仍在高速壮大。正在密集孵化的在研项目包括现场送达照片合规审查智能体、PagerDuty 突发警报故障分流排查智能体、每日核心 KPI 自动化晨报智能体，以及在现有存量智能体中进一步扩大调优者闭环的覆盖范围。

与此同时，团队正在全公司挖掘更多可以“代码化（X-as-code）”的业务载体：消息通知模板、事件路由规则、业务分发逻辑……将它们统统迁移入代码仓库，让智能体能够更自如地阅读理解、推理判断，并持续提交自动化优化提案。

正如富勒所描绘的终极图景：

> **“我们期望借助 AI 打造一家能够自主稳健运转的现代化企业，而全体员工得以从中解放出来，去掌舵这艘航船前行的方向。”**
