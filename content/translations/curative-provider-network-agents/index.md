[Curative](https://curative.com/) 专门向企业雇主销售商业健康险，其最大卖点在于：只要参保员工按要求完成一次基础体检（Baseline Visit），其在网络内就医便享有<strong>“0 元免赔额（Deductible）、0 元共付额（Copay）”</strong>的极致福利。

Curative 最早并非做保险起家。它最初是一家医学实验室初创企业，在新冠疫情期间，据其内部测算累计处理了全美约 10% 的核酸检测样本；这一契机让他们顺理成章地与全美几乎每一家主流商业保险巨头建立了业务往来。

几位英国籍创始人长年习惯了“患者就医无需自掏腰包”的国家医疗服务体系（NHS），在目睹了美国医疗体系的极其低效后，下定决心打造一家以“预防为主”的新型健康险支付方（Payer）。但很快他们发现，自己严重低估了从零搭建一张覆盖全美的自营医疗服务网络（National Provider Network）究竟有多艰难。

“在创业早期，有时‘保持天真’反而是一件好事，因为你根本不知道这件事其实是完全不可能做到的；然后在跌跌撞撞的摸索中，你想方设法让它变成可能，”Curative 首席执行官 Fred Turner 感慨道，“去年我们拼尽全力签署了 2,100 份诊所合同，这已经是前一年的两倍了；但如果每年只能签 2,000 份，我们突然意识到——**要铺满全美网络需要整整耗费 30 年**！全美如今硕果仅存的几家屈指可数的全国性医疗网络，之所以全都是大约 30 年前建成的，背后是有残酷客观原因的。”

Curative 必须以超常规的速度加速合同签署，但单纯靠人海战术疯狂招聘，根本无法填平如此庞大的鸿沟。

他们的破局之法是：打造了名为 **Gwen** 的智能体——由它全权负责推进单个医疗服务商从最初的触达沟通到最终签章的一站式全流程；同时在其周围配备了一组轻量化的辅助智能体，各司其职负责审核报价费率、把关外发消息、解答业务疑难，并在遇到非标极端报价时精准升级给人类高管把关。

## 核心谈判智能体 Gwen

Gwen 同时承接入站咨询与出站主动拓展线索。每次运行 Gwen 时，它在底层主要调用旗舰级模型 **Claude Opus**，且**单次执行只专注于一家医疗机构**，杜绝任何来自其他交易的信息串扰。

举例来说，当一家诊所在 Curative 官网上填写了入网意向表单后，Gwen 会立刻自动展开针对该诊所的背景调研，并基于采购的商业理赔数据集以及联邦法规强制要求保险公司公开的“价格透明度文件”，主动向诊所出具一套建议签约费率。在谈判过程中，Gwen 甚至会主动向诊所展示这些市场大盘参考费率，协助破冰破局。

<strong>费率审核员（Rate Reviewer）</strong>则运行在性价比更高的 **Claude Sonnet** 之上。每当 Gwen 试图开出突破标准模板上限的溢价费率时，它必须向费率审核员书面陈述理由，由审核员来判定该上调是否合理。

“在早期，我们设置了一个极其庞大的人工审批队列：只要 Gwen 想要给出一个高于模板基准的费率，就必须由人工逐笔审批。但随着时间推移，我们逐步放宽了限制。实战证明，**让第二个智能体来进行费率交叉复核，其效果远胜于直接无脑给 Gwen 放开更大权限**，”Fred 解释道。

Sonnet 费率审核员能够全自主放行大约三分之二的调价诉求；剩下那些确实极其特殊的非标情况，才会最终呈递到 CEO Fred 的案头进行最终裁决。

“最后呈递到我面前的审批，通常都来自体量庞大的大型医疗集团，或者提倡极其古怪合同条款的特例——就算我们完全不用 AI 纯靠人工推进，这类硬骨头原本也是必须由我亲自审批的，”Fred 谈道。

至于主动出击的外呼拓展（Outbound Deals），则往往需要百折不挠的惊人毅力，因为一线诊所每天都极其忙碌。很多医疗机构的最终回复，往往发生在**连续发送了第 14 封跟进邮件、外加发了整整第 9 份传真之后**。

为了筑牢对外沟通的安全防线，团队引入了一个运行在轻量极速模型 **Claude Haiku** 上的<strong>“判官（Judge）”</strong>，在每一封外发沟通正式发出之前进行逐字安全审查。Curative 之所以紧急加入这一把关机制，是因为在早期实测中，Gwen 竟然在给客户的邮件中误将团队内部探讨底线底牌的机密备忘录顺手抄送给了诊所！如今，一旦有任何违规消息被判官拦截，系统会即刻附带原因打回，由 Gwen 重新组织语言重新提交。

平均每签署一份完整合同，大约需要消耗 **2,000 万个 Token**，而这仅相当于最初粗放探索期成本的十分之一左右。这种极高的单位经济效益，直接催生了 Curative 的核心战略突破：**全力签约那些过去常年被传统大型医疗巨头网络所忽视的长尾小型独立诊所**。

“无论是面对坐拥数千张床位的巨型三甲医院集团，还是仅有一名医生的独立诊所，智能体都会极其耐心地给予完全相同水准的无微不至关注，”Fred 解释道，“站在那个智能体的视角里，眼前的这名医生就是它全世界唯一聚焦的全部中心。”

在艰苦的条款拉锯谈判中，Gwen 会对照 Curative 的官方政策规范逐条审查诊所提出的法务修改红线（Redlines），随后**自主编写并运行 Python 代码**，调用文档处理库，将双方达成的最新修订条款精准合并为一份最终版正式合同。

从最初提交意向表单到最终电子签章生效，最快的一次**全流程仅耗费了短短 1 个小时**。一旦合同签章完成，另一个独立的“医师资质审核智能体（Credentialing Agent）”会立刻接手核验该执业医师的行医执照；随后其他协同智能体自动将该诊所的主数据与费率合同录入核心数据库，以便后续的医疗理赔系统能够实时进行计费结算。

自 Gwen 正式上岗以来，Curative 的人工商务谈判团队规模仅从 45 人微增至约 55 人，但**每位员工的人均作战产出却足足飙升了约 2.5 倍**。人类工程师将前期的冷启动扫楼触达和繁琐合同文书全权交给 Gwen，自己则专注于通过电话攻坚那些高意向的高净值重点客户。更有趣的是，Curative 同样会针对 Gwen 独立谈成的合同给商务团队发放绩效提成，让真人与 AI 真正绑定在同一张业务大盘目标上。

“我们员工的日常工作，彻底从繁重的文书案头泥潭中解放了出来，转而全身心深耕真正有温度的客情信任关系，”Fred 欣慰地说道。

Fred 坚信，这种闪电般的签约节奏能够切实帮助小型独立诊所维持自主生存：“如果你新开了一家独立诊所，由于官僚作风往往需要耗费整整三个月才能通过保险公司的准入认证进驻网络，这意味着在这整整三个月里，你为患者看病是一分钱也拿不到报销的。”

Gwen 远非 Curative 内部唯一的智能体战力。另一个代号为 **Brad**、同样基于 Claude Opus 的智能体，专门负责主要通过中介经纪人渠道向企业雇主销售团体健康险。Brad 负责紧盯每一份保费报价的中介跟进进度，并通过全自动从雇员花名册 Excel 表格中清洗提取关键参保数据，帮助核保精算师彻底告别手工洗表的苦日子。

依托这套人机协同大军，**Curative 如今能在 30 分钟内，以量身定制正式函件的形式，针对客户通过电子邮件或传真发来的医疗理赔争议纠纷给出精准答复**。“在此之前，整个行业的理赔争议处理通常需要漫长的 90 天，而我们如今通过邮件或传真在 30 分钟内即可解决，”Fred 指出，“绝大多数传统保险公司都是用几张死板的标准公文模板机械拼凑，这让医疗机构极其沮丧，因为模板往往根本解释不清具体案情。而现在，医生拿到的是一封针对该单具体争议、清晰阐述底层事实与法规逻辑的定制化专业公函。”

所有这些前沿智能体的底层，全部挂载于一套专属定制的云原生核心理赔系统、事前授权系统以及财务结算中台之上——而这套底层中台系统，正是今年由 **13 位工程师在 Claude Code 的强力赋能下全面重构完成的**。在此之前，仅搭建一套传统核心理赔系统，行业普遍预估至少需要耗费整整 **100 个工程人年（Engineer-years）**。

“我们绝不是生硬地把智能体外挂在一套老旧系统上，”Fred 强调，“整套理赔系统就是跑在 AWS 上的现代化 Python 微服务，它原生自带 MCP 协议接口与标准 API，**而且代码本身就是由 Claude 编写出来的，所以 Claude 对它底层的每一行逻辑都了然于胸**。”

## 打造能与真人进行严肃商业谈判的智能体：六大硬核心得

在教智能体学会与人类展开商务博弈的过程中，Curative 团队沉淀出了以下几条宝贵心得：

1. **从单一的高效通用工具起步（Start with one general tool）**。“我们一开始曾设想为智能体专门开发各种细分小工具，但实际发现根本行不通，因为法律合同的红线批注修订（Redlining）实在太复杂多变了，”Fred 分享道，“我们最终发现最卓越的解法是：**直接赋予模型一个能够运行 Python 代码的通用执行环境，让它使用 `python-docx` 库全自主完成所有的合同红线比对与合并**。这套方案的实战表现简直完美无瑕。”
2. **在客户最舒服的渠道上相遇（Meet people on their channel）**。为 Gwen 接入自动收发<strong>传真（Fax）</strong>工具后，它的谈判成单率直接**暴涨了两倍多**！很多基层的美国医疗诊所习惯直接在打印出来的纸质传真上用手写笔批注修改，然后再原样传真发回。“这就是真正做到迎合用户的既有习惯，”Curative 首席技术官 Isaac Turner 谈道，“虽然他们人人都有电子邮箱，但面对合同公文，传真依然是他们心理安全感最强烈的渠道。”
3. **保持每次业务运行的强隔离（Keep each run isolated）**。Gwen 的每一次执行只负责面对单个医疗机构，会话结束后**绝不在不同交易之间共享任何跨会话记忆**。Curative 负责销售的 Brad 智能体虽然支持跨会话记忆，但在使用时必须极其谨慎。“智能体很容易记下一些自以为是的错误笔记，随后陷入万劫不复的‘厄运死循环’（Doom Loops）——脑海中带着一段永远清除不掉的错误记忆到处犯错，”Fred 警告道。
4. **从执行闭环的外部来推进系统自愈**。每隔几天，Fred 都会向 Claude Code 下达一段固定的提示词指令：随机抽样过去 10,000 次真实谈判运行记录，主动标出任何异常表现，并自动提交一个修复代码 PR。“最强大的自愈迭代闭环，正是通过运行 Claude Code 全面复盘海量历史实战语料，并不断向系统发问‘这处交互当初怎样才能做得更好’。”
5. **早期先在远离受保护健康信息（PHI）的安全区试水**。在相当长的一段时间内，Gwen 被严令禁止接触任何敏感的患者健康隐私信息（PHI），确保早期的试错完全局限在低风险的纯商业谈判领域。而在今天智能体确实需要触及 PHI 的生产链路上，团队部署了严密的后端访问控制网关限制入参，并对智能体的全部动作执行严苛的合规审计日志留存。同时，签署 HIPAA 规范所要求的 BAA 商业伙伴合规协议也变得越来越顺畅。“Anthropic 在以极其迅捷的速度推出符合 HIPAA 合规标准的前沿大模型服务方面做得极其出色，使我们能够在受到高度严苛监管的医疗行业中快速拥抱前沿生产力。”
6. **严密监控智能体在后台自发产生的自主行为，确保其与机构的风险偏好相符**。在实操中，当诊所随口询问能否提供一份用于向内部员工宣贯的宣传单时，Gwen 在完全没有任何预置政策指令的情况下，直接利用自己的 Python 工具自主排版画出了一份传单！还有一次，当得知某家网络内合作诊所的前台在接待参保会员时不小心拒诊时，Gwen 竟然主动给该诊所发函敦促其务必加强前台医务培训，随后还极其尽责地去主动核查该会员是否最终顺利看上了病。

## 未来版图

下一步，Curative 计划将智能体全面引入患者诊疗导航（Care Navigation），极大延展旗下 130 名专业健康指导师的服务半径。

Fred 甚至极其笃定地预言：未来的商务博弈终将走向“智能体与智能体之间的交锋”。如今相当大比例的医疗理赔申诉其实早就是由各家诊所背后的 AI 代笔撰写的，他由衷期盼未来的医疗机构也能派出智能体来与 Gwen 谈判。“商业市场上总会存在一个公允的市场出清价格（Clearing Price），越快撮合找到这个出清价，医患双方就能越早把全部精力投入到真正治病救人的核心使命中去。”

### 来自 Curative 团队的三大最佳实践

| 核心思考 | 实践解法 |
| --- | --- |
| **智能体在刚上线时应当被赋予多大权力？** | **远比你直觉认为它能承受的权力要小得多**。Gwen 最初上线时，任何超出基准模板的调价都必须排队等待人工审批。Curative 随后循序渐进地放开规则，接着引入了 Sonnet 费率审核员，而对于无法放行的疑难大单，依然牢牢由 CEO Fred 亲自把关。 |
| **当智能体不可避免地犯错时怎么办？** | **提前做好预案，并与人类 baseline 进行客观对标**。“达标线绝不是要求机器 100% 完美无瑕，”CTO Isaac 谈道，“真正的衡量标准在于：如果你真的人工雇佣了 1,000 名员工去逐一谈判签合同，人类所犯下的让你追悔莫及的低级失误，难道就会比机器更少吗？” |
| **如何对数十万条全自动发出的对外消息进行有效审计？** | **记录一切全量日志**，在每一条外发消息的出口处挂上严密的“判官”智能体进行终审把关，并定期由 Claude Code 对海量真实会话进行自动化抽检自查。 |
